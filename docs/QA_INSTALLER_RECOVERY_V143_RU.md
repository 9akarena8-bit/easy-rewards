# QA: Windows beta — скачивание, проверка и восстановление после обновления

**Статус:** автоматические сценарии добавлены, **ручной откат на Windows не выполнен**.
База: интеграционный кандидат PR #37, исходный SHA
`5b39fe90fa4a5395c5cec488cd0503de5f46a842`.
Относится к #21 / #25; релиз, `main` и действующий установщик не изменять.

## Что именно проверяет код

- Установленный EXE использует `release_updater.py`: только опубликованные
  non-draft/non-prerelease GitHub Releases новее текущего `VERSION`,
  ожидаемое имя, допустимый URL, ограничение размера и SHA-256.
- Файл сначала сохраняется как `*.download`; только после сверки размера
  и SHA-256 переносится в `*.exe`. При ошибке загрузки временный файл удаляется.
- `backend.update_install()` повторно проверяет SHA-256 перед запуском Inno Setup;
  автоматическая проверка в фоне лишь **скачивает**, а не запускает EXE.
- Старый ZIP-обновлятор `updater.py` умеет создавать `_backup`, **но это
  не механизм возврата установленной Windows-сборки через Inno Setup**.
  Нельзя считать проверку ZIP-бэкапов тестом Windows rollback.

## Существенное ограничение текущей беты

PR #37 собирает `EasyRewards_Setup_1.4.2.exe` и сохраняет встроенный
`VERSION=1.4.2`. Поэтому автообновлятор, который ищет **более новую**
публичную GitHub Release, не обновит опубликованную v1.4.2 до данного
кандидата: номера версий одинаковы. Для оценки PR #37 нужен **ручной запуск
проверенного EXE**. Это отдельный сценарий от настоящего in-app update.

## Ручная приёмка на двух Windows-ПК

1. Записать Git SHA, SHA256 **самого EXE**, Windows 10/11, выбранный язык
   установщика. Не использовать неизвестные копии файла; оба тестировщика
   должны иметь один и тот же SHA256.
2. До установки закрыть лаунчер и сохранить **локальную приватную** копию
   каталога пользовательских данных `%LOCALAPPDATA%\EasyRewards`
   (см. `paths.py`). В нём могут быть секреты; в GitHub и отчёты не отправлять.
   Сохранить отдельно версию опубликованного официального установщика v1.4.2
   и проверить его хеш/источник.
3. Выполнить чистую установку кандидата и установку **поверх v1.4.2** отдельно.
   Проверить открытие, закрытие и повторный запуск, локальные настройки,
   конфигурацию Discord без раскрытия webhook, новости offline.
4. На тестовой машине проверить **прерывание скачивания и отсутствие запуска
   неподтверждённого EXE**. Тесты `tests/test_release_integrity_qa_v143.py`
   подтверждают только файловую логику с подменённой сетью, не физическую сеть.
5. Если новая сборка не запускается, закрыть её, переустановить проверенную
   опубликованную v1.4.2 вручную, открыть приложение и проверить чтение
   прежних настроек. Если совместимость данных нарушена — закрыть программу
   и восстановить **сохранённую локальную копию данных**; записать шаги и ошибку.
6. Зафиксировать длительность, ошибку, логи **без секретов**, хеши
   установщиков, статус **PASS / FAIL / NOT TESTED** для каждого ПК.
   При отказе не распространять кандидата и не утверждать, что откат готов.

## Автоматизированная матрица

| Проверка | Тест | Ожидаемый результат |
| --- | --- | --- |
| Разрыв соединения при загрузке | `test_interrupted_download_never_promotes_partial_installer` | Старый файл не перезаписан, частичная загрузка очищена |
| Неверный SHA256 при правильном размере | `test_same_size_checksum_mismatch_does_not_replace_cache` | Невалидный EXE не продвигается |
| Действующий кеш | `test_verified_cache_is_reused_without_network_access` | Загрузка не повторяется |
| Повреждённый кеш | `test_corrupt_cache_is_replaced_only_after_verified_download` | Проверенный файл заменяет повреждённый |
| Очистка кеша | `test_cache_cleanup_keeps_future_update_and_unrelated_files` | Будущий установщик остаётся |

Прогон: `python -m pytest -q tests/test_release_integrity_qa_v143.py`.

**Не подтверждено до ручной проверки:** Inno Setup rollback, сохранность
настроек после реального downgrade, работа автообновления на настоящем
следующем публичном релизе, Windows/UAC/антивирус, и запуск нового UI.
