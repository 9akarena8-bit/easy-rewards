# Подписки и офлайн-лицензии · #24 / #30

Приватная Windows-бета работает с `SALES_ENABLED=0`. Для личной проверки и выдачи доступа друзьям сервер не нужен. Доступ выдаёт владелец, срок хранится в подписанном JSON-файле. Демо-заказы и реферальные скидки остаются в отдельном локальном сервисе для последующего подключения.

## Подготовить ключ владельца

Из корня проекта в PowerShell. Используйте отдельную папку под своим профилем, вне исходников, сборки и общих каталогов.

```powershell
$env:SALES_ENABLED = '0'
$ownerDir = Join-Path $env:LOCALAPPDATA 'FPT-Owner-Licensing'
python -m pip install -r merchant_service/requirements-offline.txt
python -m merchant_service.owner_license --owner-dir $ownerDir init
```

Утилита попросит придумать и повторить пароль. В сборку включается **только** публичный файл `license-public.pem`. Для действующего установщика интегратор копирует его как `assets/license-public.pem` перед упаковкой и устанавливает `cryptography` в среду сборки. Приватный ключ, пароль и журнал `issued-licenses.sqlite3` остаются у владельца. Получателю отправляется только его подписанный JSON. Храните резервную копию ключа и журнала. Смена пары ключей делает ранее подписанные лицензии несовместимыми с новой сборкой.

## Бесплатный тест для владельца или друга

1. В установленном лаунчере откройте «Подписка», скопируйте ID установки и передайте его владельцу.
2. Владелец выпускает лицензию на нужный срок. Пример на 7 дней. Уникальный `friend-001` сохраняется у владельца для повторной отправки.
3. Получатель вставляет содержимое JSON в окно активации лицензии. После перезапуска лаунчер повторно проверяет подпись и срок по тому же ID установки.

```powershell
python -m merchant_service.owner_license --owner-dir $ownerDir issue `
  --installation '<ID установки из лаунчера>' --days 7 --method friend `
  --reference friend-001 --output (Join-Path $ownerDir 'friend-001.json')
```

Одинаковый reference, ID, способ и срок возвращают тот же документ. Повтор с изменёнными параметрами отклоняется. Новый reference для той же установки добавляет срок после текущего активного периода. Для нового компьютера или новой установки требуется новый выпуск. Подпись защищает документ от изменения, но офлайн-проверка использует часы Windows и не обеспечивает удалённый отзыв. Граница окончания срока проверена тестом с управляемым временем.

## Сверка владельцем

Банк и Steam пока доступны как демо-заявки. Перед любым будущим ручным выпуском по оплате владелец сверяет заказ и фиксированную сумму с фактическим поступлением или окончательным Steam-обменом. Скриншот покупателя и отметка «Оплатил» не подтверждают получение. Для Steam необходимо дождаться окончания hold и периода возможного отката, где они применимы.

Режим ручного выпуска поддерживает `--method bank_transfer` и `--method steam_items`, срок 1, 3 или 7 дней и явное `--confirm-reconciled`. В `--reference` указывают один стабильный идентификатор операции. Команда подписывает лицензию, никакие платёжные операции не запускает. Не передавайте утилите банковские реквизиты, документы или Steam-секреты. В текущей сборке сценарий с реальными средствами не запускается.

## Контракт лаунчера и сборки

- `merchant_service.offline_license.verify_license(document: dict, public_key_pem: bytes, installation_id: str)` возвращает проверенные claims либо поднимает `ValueError`. Формат файла — `{"payload": {...}, "signature": "<base64>"}`. Claims v1 включают `license_id`, `installation_id`, `issued_at`, `expires_at` (Unix seconds) и `access` (`friend` или `paid`).
- Bridge `offline_activate(document: str)` принимает JSON и должен сохранить его только после проверки комплектным публичным ключом. Состояние `offline_access` содержит `installation_id`, `configured`, `active`, `expires_at` и, при действующей лицензии, `access`. Для `friend` показать «Бесплатный тестовый доступ» с датой окончания. ID установки должен переживать обновление. Подпись, содержимое лицензии и пароль исключаются из отчётов.
- До упаковки добавить зависимость `cryptography` в среду сборки и в зависимости CI, которые запускают полный pytest. Проверить, что в EXE вошли проверяющий модуль, зависимость и публичный ключ. Проверку установщика для друзей выполнить без `FPT_OWNER_TEST` и без запуска локального сервиса. Личные ключи, журнал и утилита выпуска в клиенте не требуются.
- Макеты `subscriptions.jpeg` и `checkout-referral.jpeg` задают 1/3/7 дней (59/129/249 ₽) и перевод/Steam. Коды, счётчики и скидки на макете относятся к будущему серверному режиму. Без него не показывать ссылку и счётчики как действующие.
- Будущий локальный протокол остаётся отдельным. `GET /api/v1/referral` возвращает состояние после входа покупателя, `POST /api/v1/referral` принимает `{"code":"…"}`. 10% доступны обеим сторонам после первого подтверждённого демо-перевода. Бесплатная офлайн-лицензия реферальную покупку не создаёт.

## Проверки

`python -B -m unittest discover -s merchant_service/tests -v` — 23 теста на Windows. Проверены изменение claims и подписи, чужая установка и чужой ключ, граничный срок, повтор и параллельный выпуск, возврат, изоляция покупателей и владельца, CSRF, откат подтверждения, запрет выдачи по Steam-заявке и снятие реферальной скидки после возврата. Тесты используют временные ключи и базы.

Перед выдачей друзьям остаётся проверить один собранный Windows-установщик с публичным ключом владельца и выдать по нему первую бесплатную лицензию. Этот файл не содержит ключей и реквизитов.

Дополнительно пройдены сценарий Edge «покупатель → вход владельца → подтверждение → возврат → выход» и проверка Python bridge без сервера с временным публичным ключом (активация, перезапуск, чужой ID, истечение). В общем pytest на промежуточном состоянии рабочей папки остались 3 падения за пределами merchant_service. Два старых UI-теста ждут прежнюю разметку и фон. Тест архива релиза захватывает служебные файлы из локальных `edge-design-*` (в том числе `arbitration_service_config.json`), поэтому архив нужно формировать из чистого снимка проекта.
