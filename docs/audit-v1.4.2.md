# Аудит Fortnite Pirate Token 1.4.2

Проверена версия `v1.4.2` на коммите `ebc0ee107f2b0a8cbbccf6142025d9e49a54e7a1`. Исправления подготовлены в ветке `fix/v1.4.2-window-controls`.

## Найденные причины

| Область | Наблюдение | Исправление |
| --- | --- | --- |
| Обнаружение Fortnite | На запущенной игре исходный поиск возвращал окно `FortniteClient-Win64-Shipping_EAC_EOS.exe`. Служебный процесс проходил проверку по префиксу имени. | Поиск исключает известные служебные процессы и предпочитает видимое окно с заголовком и подтверждённым игровым процессом. Проверка фокуса читает заголовок у того же окна и перепроверяет активный дескриптор. |
| Старт и остановка | Обновление интерфейса отключало «Стоп» между постановкой запуска в очередь и стартом рабочего потока. | «Стоп» доступен с момента, когда Python сообщает о запуске в очереди. «Пауза» доступна при работающем движке. |
| Диагностика | Начальный асинхронный поиск отображался как «Окно не найдено». Ошибки запуска и новые причины ожидания могли отсутствовать на уже открытой вкладке. | Интерфейс показывает ход и ошибку поиска, обновляет причины ожидания, ошибки запуска и ввода без перестройки страницы. |
| Anti-AFK и HUD | Ожидание HUD каждый раз переносило уже наступивший срок следующего действия ещё на секунду. После подтверждения HUD это давало лишнюю задержку, особенно при мерцании распознавания. | Срок следующего действия сохраняется. Ввод по-прежнему ожидает два кадра с подтверждённым HUD при активных шаблонах лобби. |
| Anti-AFK и Replay | Задержка захвата могла пропустить действие Anti-AFK, пока движок ожидал Replay или выход из экрана результатов. | Ожидание Replay блокирует ввод и при задержке захвата. |
| Пауза и остановка | После остановки с паузы движок сохранял флаг и причину паузы до следующего запуска. | При завершении потока состояние паузы сбрасывается. |

## Проверки

- Windows, Python 3.11.9: `py -3.11 -m pytest -o addopts='' -q` — 157 тестов прошли. Покрыты отмена запуска, повторный запуск, пауза и остановка во время захвата, потеря фокуса, подтверждение HUD, выбор окна и диагностика.
- Node: `node --test --test-isolation=none tests/*.test.cjs` — 9 тестов прошли. Покрыты доступность «Стоп» при запуске в очереди, обновление диагностики и отсутствие повторной отправки команды на одном клике.
- Проверены синтаксис Python и JavaScript и `git diff --check`.
- Windows: основной лаунчер открыл WebView2, загрузил интерфейс и получил версию `1.4.2` через API. Режим `--classic` открыл Tk. Оба тестовых окна закрылись штатно с временными настройками и отключёнными горячими клавишами.
- На запущенной игре исправленный Win32-адаптер определил окно `Fortnite` и процесс `FortniteClient-Win64-Shipping.exe`. Проверка только читала сведения об окне. Запуск Fortnite из Epic проверен через тестовый адаптер.

## Границы проверки

- Реакцию Fortnite на ввод, работу Anti-AFK в живом матче и фактический запуск игры через Epic Launcher в этом прогоне не проверяли.
- Захват кадра по-прежнему использует основной дисплей. Для Fortnite на другом мониторе распознавание HUD и Replay требует отдельной проверки координат.
- В классическом Tk запуск напрямую вызывает загрузку шаблонов на потоке интерфейса. При медленном чтении с диска окно может временно перестать отвечать. Неблокирующий запуск с очередью проверен для WebView2.
