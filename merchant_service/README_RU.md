# Fortnite Pirate Token — Telegram-бот с подпиской

**Статус:** серверный MVP с Telegram Stars, SQLite, выдачей ключа, проверкой срока и выдачей установщика. **Не внедрён в основной EasyRewards**, публичный сайт и платежи в реальности не подключены: нужны токен бота, сервер/HTTPS и цены. Сам по себе ZIP не защищает скачиваемую программу от копирования и не делает платную версию готовой.

## Сначала — безопасность исходников

Текущий репозиторий проекта `9akarena8-bit/easy-rewards` публичный. Для коммерческой утилиты нужно сначала выбрать архитектуру приватного репозитория и отдельно распространяемого EXE. Код Python в EXE можно извлечь/изменить. Даже после перевода GitHub в private уже полученные другими людьми копии нельзя отозвать. Реальную критичную функциональность, которую нужно строго защитить, следует выносить на сервер — если её вообще возможно выполнить удалённо. Нельзя обещать защиту от взлома 100%.

## Что делает готовая серверная часть

- Telegram `/start`, `/plans` и `/terms`: тарифы 1/3/7/30 дней; цены задаёшь **сам**, в Stars.
- `sendInvoice` (`XTR`) → `pre_checkout_query` → только `successful_payment` → автоматическое продление. До оплаты обязательно согласие с условиями, и продажи по умолчанию отключены.
- Одна лицензия на Telegram-пользователя, период суммируется, повторная доставка сообщения не удваивает оплаченный срок.
- `/license`: тот же ключ и окончание подписки; `/download`: одноразовая ссылка на установщик на 15 минут.
- Онлайн-проверка по `POST /v1/activate` и `POST /v1/check`, привязка первого устройства к лицензии.
- `/paysupport` — направление сообщения владельцу бота, если пользователь указал проблему.
- Для администратора `/grant TG_ID ДНИ`, `/resetdevice TG_ID`, `/refund TELEGRAM_CHARGE_ID`.
- Секрет лицензий, токен бота и база должны храниться только на сервере.

## Запуск (Windows, Python 3.11)

1. Открой Telegram → [@BotFather](https://t.me/BotFather) → `/newbot` → создай бота и сохрани полученный токен. **Никому не присылай токен в чат или GitHub.**
2. Скопируй `.env.example` как `.env`. Заполни `BOT_TOKEN`, `ADMIN_USER_ID` (числовой Telegram ID администратора), `LICENSE_SECRET` (не менее 32 случайных символов) и цены Stars: `PLAN_DAY_STARS`, `PLAN_THREE_DAYS_STARS`, `PLAN_WEEK_STARS`, `PLAN_MONTH_STARS`. Можно оставить неиспользуемые тарифы по 0 — они будут скрыты.
3. Создай папку `installer` и помести в неё свой установщик под именем `FortnitePirateTokenSetup.exe` (либо укажи иной путь в `INSTALLER_PATH`). **Только установщик без исходников/секретов.**
4. Разверни службу на постоянно работающем сервере с доменом и HTTPS (например, nginx/Caddy reverse proxy → `127.0.0.1:8765`). Поставь `PUBLIC_BASE_URL=https://твой-домен`. На Windows за NAT домашний ПК без публичного HTTPS-адреса не обеспечит пользователям доступ. Не открывай 8765 напрямую в интернет по HTTP.
5. До запуска реальных продаж опубликуй свои условия оказания услуг/возвратов и укажи `TERMS_URL=https://...` и `TERMS_VERSION=v1`. **Оставь `SALES_ENABLED=0`, пока приложение не интегрировано и не протестировано полностью.** Для тестового Telegram API можно выставить `TELEGRAM_TEST_MODE=1` (нужны отдельные тестовый аккаунт и бот).
6. Запусти `START_BOT.bat` (или `py -3.11 service.py`). Проверь `https://твой-домен/health`: `{"ok":true,"service":"license"}`.
7. **До реальных покупателей** проверь всё в Telegram Stars test environment (отдельный тестовый бот/сервер/база), оплату, повтор платежа, скачивание, продление, блокировку, возврат и историю платежей. Убедись, что служба работает после перезагрузки сервера. После полного тестирования можно выставить `SALES_ENABLED=1`.

База `private/licenses.db`, файл `.env` и резервные копии — **никогда не помещать в публичный репозиторий**. Ограничь права доступа к файлам, храни защищённые резервные копии. Отдельно продумай политику конфиденциальности, условия возвратов, обязанности по налогам и работу с пользователями.

## Интеграция в реальный Windows-лаунчер

`license_client.py` содержит клиентское обращение к HTTPS API. Но **это только строительный блок**: в текущей версии EasyRewards модуль `subscription_preview.py` всё ещё возвращает фиктивный статус. Для реального платного релиза нужно **внести проверку непосредственно в `backend.py`/`core.Engine`** (и все прямые способы запуска, включая горячие клавиши F7 и классический интерфейс), добавить ввод ключа и реальную дату подписки в `ui`, регулярно перепроверять лицензию и останавливать платный модуль после окончания срока. Проверять только текст в интерфейсе бесполезно — пользователь сможет обойти его.

При интеграции нужно добавить кнопку «Открыть Telegram-бота» с реальным username и механизм загрузки ключа. **Не вводи в клиент BOT_TOKEN, LICENSE_SECRET и доступ к SQLite**. Сервер остаётся единственным источником истины по оплате.

Для проверки клиента используй `LicenseClient("https://твой-домен")` и методы `activate(key)`, `check()` — их нужно вызвать из основного кода, а не только из визуальной кнопки.

## Проверка без денег

`TESTS.bat` или `py -3.11 -m unittest discover -s tests -v` — тесты модели лицензий, повторов платежей, привязки устройств, скачивания, возврата и истечения.

Сервис намеренно не содержит реальных токенов/платежей и не пополняет счёт сам. Пока не настроены HTTPS, BotFather, цены и интеграция приложения, **не принимай реальные оплаты**.

## Telegram Stars vs банковские карты

Для цифровых товаров и услуг **внутри Telegram-ботов/мини-приложений** Telegram требует Stars (`XTR`). Внешний сайт с оплатой картой/СБП можно сделать отдельно, соблюдая требования платёжного провайдера и действующее законодательство; внутри бота нельзя подменять встроенную оплату сторонней кассой. Источник: https://core.telegram.org/bots/payments-stars

## Новое: демо-центр карты, СБП, QR, переводов и скинов (12.11.2026)

Самый простой запуск **без BotFather, токенов и платёжных реквизитов**:

1. Скачай ZIP, распакуй в отдельную папку.
2. Дважды нажми `START_DEMO.bat` (на Windows должен быть Python 3.11).
3. Откроется `http://127.0.0.1:8797/` с тёмно-синим/золотым интерфейсом подписок.
4. Выбери тариф, карту/СБП/QR/перевод/скины и нажми **«Создать заявку без оплаты»**.
5. В локальной базе `private/external_demo.sqlite3` создаётся неплатёжный черновик. Это не заказ продавцу, не счёт, не чек и не лицензия. Ввод реальных реквизитов запрещён.

В демо можно выбрать Dota 2, Rust, CS2, TF2, PUBG, Don't Starve Together и NARAKA, внести условные названия и оценки предметов. Инвентарь Steam не подключён, ссылки для трейда не создаются. CS2 имеет 7-дневную защиту обменов. По другим играм сроки блокировок проверяются для конкретного предмета.

`external_orders.py` содержит изолированную SQLite-модель демо-заказов, а `demo_checkout.py`, `demo_checkout.html`, `demo_checkout.js` — страницу и локальный сервер, который слушает **только 127.0.0.1**. В демонстрационном API **нет ни `mark_paid`, ни `grant`, ни возможности выдавать доступ**. После подключения коммерческой кассы понадобится отдельная доверенная интеграция на сервере. Для цифровых подписок в Telegram разрешены только Stars — внешние методы не продаются из бота. `/demo` покажет состояние оплаты.

### Подготовка к реальному запуску (пока ничего не подключено)

- Бот: Telegram Stars (`XTR`) только в тестовом окружении до выпуска; затем истинное событие `successful_payment`, идемпотентный учёт и серверная активация.
- Карта/СБП/QR: корпоративный или иной подходящий мерчант-аккаунт и checkout провайдера, вебхуки и повторная проверка состояния платежа через API.
- Перевод: реальное поступление должно проверяться выпиской продавца и сопоставляться по номеру заказа и точной сумме; скриншот пользователя не подтверждает платёж.
- Скины: партнёрская интеграция, верифицированные цены, проверка trade offer/владения/ограничений/окончательности. Steam **не рекомендует** обменивать предметы на вещи вне окна обмена; данный канал несёт высокий риск.
- Лицензии: клиент в текущем основном репозитории ещё не связан с сервером. После законного подтверждения оплаты сервер выдаст ключ; EXE будет проверять право доступа. До этого продавать подписку нельзя.

Для проверки работы сервера (без токена и интернета): `py -3.11 -m unittest discover -s tests -v`. Никаких реальных платежей, адресов для переводов или Steam-паролей в архиве нет.
